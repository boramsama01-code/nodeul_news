# 노들섬 뉴스 모니터 — 독립 실행 안내

## Windows 실행

Windows 64비트용 `Nodeul-News-Windows.zip`을 원하는 폴더에 압축 해제한 뒤 **start-desktop.cmd**를 더블클릭하세요. Node.js·PostgreSQL이 포함되어 있어 Docker나 Replit 설치가 필요 없습니다. 처음 실행하면 데이터베이스를 준비하고 GitHub 저장소에 있던 기사 백업을 한 번 가져옵니다. 브라우저에서 `http://localhost:8080`이 열립니다.

**설정 → 네이버 API 키 등록**에 Replit에서 사용하던 `NAVER_CLIENT_ID`와 `NAVER_CLIENT_SECRET`을 넣고 저장하세요. 키를 채팅이나 GitHub에 올리지 마세요. 저장 후 **데이터 수집 → 크롤링 실행**으로 확인할 수 있습니다. 다른 수집 작업이 진행 중이면 완료 후 실행하세요. 설정은 다음 자동 수집에도 적용됩니다.

브라우저를 닫아도 실행 프로그램이 켜져 있으면 수집은 계속됩니다. 종료할 때는 **stop-windows.cmd**를 실행하세요. PC 종료·절전 동안에는 수집이 멈춥니다. 재부팅 후 start-desktop.cmd를 다시 실행하세요. 시작 프로그램 등록이나 절전 설정은 자동으로 변경하지 않습니다.

프로그램은 이 PC에서만 접속하도록 설정되어 있습니다. 다른 컴퓨터에서 접속하거나 PC가 꺼져 있어도 사용하려면 별도 서버로 옮겨야 합니다.

## 데이터와 백업

- 실제 데이터·설정은 설치 폴더의 `.local`에 저장됩니다. 이 폴더를 삭제하지 마세요.
- `.local/backups`에는 실행 중 하루 한 번 기사 백업이 생성됩니다. 프로그램이 계속 켜져 있으면 매시간 백업 여부를 확인합니다. 당일 첫 백업 이후 변경 내용은 다음 날 백업에 반영됩니다.
- 새 버전으로 교체할 때 기존 `.local`과 `.env`를 보존하세요. 업데이트 전 stop-windows.cmd로 종료하세요.
- 다른 PC로 전체 이동하려면 프로그램을 종료한 뒤 설치 폴더 전체를 복사하세요.
- SQL 기사 백업을 복원하려면 실행 프로그램을 종료한 뒤 백업 파일을 **import-backup.cmd** 위에 끌어 놓으세요. 기존 `(기사 URL, 수집 출처)`가 일치하는 기사는 덮어쓰지 않습니다. 기사 추가·수정·휴지통 상태를 포함한 전체 복구는 종료 상태의 `.local` 폴더 복사본을 사용하세요.
- 동봉된 `backup/nodeulnews_data.sql`은 GitHub 커밋 `9af9b6f`에 있던 저장본입니다. 새 DB 기준 중복을 제외한 6,041개 기사 행이 들어옵니다. 현재 Replit DB와 같다고 보장할 수 없습니다. 서로 다른 포털에서 발견된 동일 기사나 과거 파생 행이 포함될 수 있어 고유 뉴스 6,041건이라는 뜻은 아닙니다.

## 수집 방식과 수정 내용

기존 자동 수집은 웹 서버 안의 자정 타이머였습니다. 서버가 중지되어 있으면 실행되지 않고, 재시작 보충 수집도 최근 하루에 한정되었습니다. 직접 RSS는 최신 기사만 제공하므로 하루 한 번 확인하면 사이에 빠진 기사를 놓칠 수 있습니다.

수정본은 별도 수집 프로세스에서 기본 30분마다 최근 3일과 오늘을 겹쳐 검색합니다. 한 번의 수집이 끝난 후 30분을 기다립니다. 마지막 완료 시간을 저장하고 재시작하면 그 이후 기간을 재검색합니다. RSS 보관기간·검색 결과 한도 때문에 과거 누락 기사를 전부 복원할 수는 없습니다.

네이버 API는 날짜 검색 매개변수가 없습니다. 이전 코드는 같은 최신 결과를 월별로 반복 요청했지만, 월 분할만으로 검색어별 최신 1,000건 한도를 넘을 수는 없습니다. 수정본은 같은 요청 반복을 줄이고 한도 도달을 진단에 표시합니다. 하루 25,000회는 호출 횟수 한도이며 하루 신규 기사 수가 아닙니다.

구글뉴스는 요청한 기간을 검색어에 포함하도록 수정했습니다. 직접 RSS가 실패하면 해당 매체의 구글뉴스 검색으로 보완하고 출처도 구글뉴스로 기록합니다. 국민일보·서울신문은 실제 응답을 확인한 RSS 주소로 갱신했습니다. 동시에 너무 많은 RSS를 요청하지 않도록 4개로 제한했습니다.

다음 수집은 카카오 API를 쓰지 않는 웹 검색 방식입니다. 카카오 키가 필요하다는 잘못된 화면 안내를 제거했습니다. 날짜 추출 보완과 페이지 반복 감지를 추가했지만, 다음 검색의 과거 결과 제한 자체가 해결된 것은 아닙니다. 네이버 웹 검색 403이나 언론사 RSS 404는 수집 이력에서 확인할 수 있습니다.

네이버 웹의 상대 날짜를 한국 시간으로 해석하도록 고쳤습니다. 저장 실패는 중복으로 처리하지 않습니다. 수집처 오류와 후보 수·신규 저장 수·중복 수를 이력에 남깁니다. 대량 수집이 포털 기사를 `media_direct` 행으로 다시 복제하던 처리는 제거했습니다. 기존 데이터의 과거 파생 행은 그대로 보존합니다.

- 기존 GitHub 기사 백업 6,041행 추가, 같은 백업 재실행 0행 추가, 백업 파일 생성 확인.
- 홈페이지·수집 페이지·설정·최근 이력 API 응답 확인.
- 네이버 키가 이 작업 환경에 전달되지 않아 실제 네이버 API 호출은 검증하지 못했습니다. API 요청 동작은 모의 응답 테스트로 검증했습니다.
- 모든 언론사의 실수집 성공이나 연말까지 무중단을 보장하지 않습니다. 일부 직접 RSS는 실패하며 구글뉴스 보완 검색을 사용합니다.
- GitHub 원격 저장소와 Replit 운영 앱에는 아직 반영하지 않았습니다. 함께 제공되는 소스 ZIP은 수정본 전체입니다.

## 개발용 소스 / 이후 서버 이전

소스 ZIP은 실행 바이너리가 아닌 개발용입니다. Node.js 22 이상과 pnpm 11.19.0을 사용합니다. `pnpm install --frozen-lockfile`, `pnpm typecheck`, `pnpm test`, `pnpm build:standalone`으로 검증·빌드합니다.

서버에서는 `.env.example`을 `.env`로 복사하고 비밀번호·네이버 키를 입력한 뒤 `docker compose up -d --build`로 웹·수집·DB를 실행할 수 있습니다. DB 비밀번호는 영문·숫자로 된 긴 무작위 값을 사용하세요. 기본 접속 주소는 서버 내부의 127.0.0.1:8080이며 DB는 외부에 공개하지 않습니다. 공용 접속에는 HTTPS와 APP_PASSWORD 설정이 필요합니다. Docker 실행 자체는 이번 Windows 환경에 Docker가 없어 검증하지 못했습니다.

초기 DB에만 deploy/init.sql을 사용합니다. 기존 DB에 자동 스키마 삭제·교체를 수행하지 않습니다. 단발 수집은 `docker compose run --rm worker node dist/worker.mjs --once 2026-09-01 2026-09-11`, 진단은 `docker compose run --rm worker node dist/diagnose.mjs`를 사용합니다. `--all` 옵션은 전체 RSS를 검사합니다.
